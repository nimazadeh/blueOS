# Blue Studio OS — Media System (Phase 2 implementation)

This is the implementation doc for the media system shipped in Phase 2.
`media-architecture.md` holds the Phase 0 design; this doc is authoritative
for what is actually implemented.

## 1. Storage model

- Originals live on the **`media` disk** (`private` by default — outside the
  public webroot). Directory layout: `{uuid}/{original-filename}`? No —
  sanitized: `{model-collection}/{slug-or-uuid}/{sanitized-filename}`
  generated by `MediaService`, never trusting the client name.
- `storage/app/media` is never symlinked into `public/` (Phase 0 design
  explicitly deferred public symlink; delivery goes through the controller).

## 2. Registry (`media` table)

Every file has a row: `model_type`/`model_id` (morph, nullable for library
uploads), `collection` (`covers|gallery`), `filename` (stored name),
`path`, `disk`, `mime_type`, `size`, `width`, `height`, `alt_text`.

There is no separate `media_versions` table in Phase 2 — images are served
full-size (no thumbnails/resizer yet). Rendering uses `cover()`/`gallery*()`
with built-in aspect-ratio boxes; the resizer is a Phase 3 candidate
(documented in `media-architecture.md`).

## 3. Service API (`App\Core\Media\MediaService`)

```php
$media->attach(
    ?Model $model,          // null = unattached library upload
    UploadedFile $file,
    string $collection = 'covers',
    bool $replace = false,  // only meaningful when $model is set
    ?string $altText = null
);
$media->deleteFile(Media $media): bool;   // removes registry row + file
```

Rules:
- Validation happens at the boundary (FormRequest rules + an internal
  `validate()` called by the service) — MIME sniff + dimensions from real
  contents; SVG rejected always.
- `$replace = true` deletes the previous file in the same collection before
  storing the new one — only when a model is attached. Library uploads always
  append.
- Model name is stored via the model's morph map (`App\Domains\…` classes);
  `Media` never reaches into domain code.

## 4. Delivery (`GET /media/{media}`)

- Route: `media.show` (`routes/web.php`), controller
  `App\Http\Controllers\Public\MediaController`.
- Access rule: **publicly visible = the media is attached to a published
  entity** (`products/portfolio/services` with `status = published`);
  otherwise only an authenticated Blue Control operator may fetch
  (library/unattached or draft/archived media).
- Files untouched by response headers: `Cache-Control` private/public
  depending on the access path; `Content-Type` from the DB row (not from the
  request).
- No `->file()` passthrough that would expose the storage path.

## 5. Trait (`App\Domains\Media\Concerns\HasMedia`)

`media()` (morphMany), `mediaFor($collection)`, `cover()` / `coverUrl()`,
`galleryMedia()`. All collection getters prefer the **already-loaded**
relation — admin/public list queries eager-load `mediaWithCollections`
(scope `withMedia()` on the models) so cards never N+1.

## 6. Admin media flow

- Upload via `admin.media.store` (FormRequest, image-only, collection
  select) — library item (model null) or attach on product/portfolio forms.
- Inline per-entity upload on product/portfolio edit pages replaces
  `covers` (radio) / appends to `gallery`.
- Alt text edited via `admin.media.update` (never null for attached files;
  library items may leave empty until attached).
- Delete: `admin.media.destroy` requires `media.delete` → media permission
  (`media.manage`); removes file + row; attached entities keep their data.

## 7. Security notes

- SVG rejected (embedded script / external entity risk) at every boundary.
- MIME allowlist checked against actual contents; dimension caps 8000×8000;
  size cap 12 MB.
- Files stored with sanitized names; no user-controlled paths.
- Public route never streams library/draft media; operator access requires
  `auth:admin`.
- Delete cascades from domain code (`MediaService::deleteFile`) — no direct
  DB cascade relies on morph guesswork.

## 8. Test coverage

`tests/Feature/Media/MediaTest.php` covers: store validation, SVG rejection
(with a real fake-SVG fixture), attach+upload on products, cover replacement,
public delivery rules (published vs draft vs library), alt-text update, delete
cascade, guest redirects. Helpers `pixelPng()` / `fakeSvg()` live in the test
file.
